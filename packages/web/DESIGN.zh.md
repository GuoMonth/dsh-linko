# Linko 收件箱 — 设计说明

[English](DESIGN.md) | 中文

## 本包是什么

Linko 节点的人机界面：渲染信封封面、记录决定与回执、撰写新消息。它不包含节点实现，
也没有自己的传输层——它是一个本机节点 REST 接口的客户端，要么与该节点通信，要么
明确说明无法通信。

文案以中文为主、英文为辅：第一批读者说中文，而协议词汇是英文。

## 数据契约

界面是三份文档的视图，除此之外不发明任何东西：

- [spec 0002](../../docs/specs/0002-message-envelope.md)——信封组成、四种署名类型，
  以及投递、已读、确认和动作是**相互独立的事实**这一规则。
- [spec 0005](../../docs/specs/0005-state-and-storage.md)——状态维度、游标作用域，
  以及持久事件与本地私有行之间的区分。
- [spec 0003](../../docs/specs/0003-lan-sync-and-transport.md)——REST 接口。

`src/model.ts` 以纯函数承载该契约，且不依赖 DOM，因此浏览器与
`scripts/smoke.mjs` 运行的是同一份代码。`src/api.ts` 是唯一发起网络请求的地方。

使用的接口：`GET /v1/node`、`GET /v1/sync`、`GET /v1/peers`、
`POST /v1/receipts`、`POST /v1/send`。

## 独立性：被强制，而非被承诺

本包中不存在合并后的消息状态。详情视图并排渲染每个维度，并给出使其保持独立的规则；
每个维度只从各自的输入推导。

该性质是被测试的，而不是被声称的：冒烟检查把某设备标记为已读，然后验证投递、
确认和动作事实均未移动。呈现状态以明确的比率报告（`read:1-of-2`），从不以布尔值
表示，因此聚合结果无法暗示"所有设备都已读"。

## 决定是提交，不是结果

一个决定始终是一次**提交**，绝不是本地结果：

| 本地状态 | 含义 | 用户看到 |
| --- | --- | --- |
| `pending` | 回执正在提交 | "正在提交…"，按钮已撤下 |
| `confirmed` | 节点已接受 | 已记录；此后动作事实以节点为准 |
| `failed` | 被拒绝或无法连接 | "决定未提交"，附原因与重试 |

在节点接受回执之前，动作事实**不会**移动；失败也绝不会被渲染成成功。本界面不提供
撤销控件，因为节点的状态转移表把已决定的动作视为终态——提供一个无法兑现的按钮
等于说谎。界面会说明这一缺失，而不是默不作声。

"搁置"是另一件事：一个仅存在于本机的标记，不改变节点上的任何状态，并已标注为
留在本设备。该标记带有时间戳，因此会跨刷新保留；加载时会清理损坏或超过 30 天的
记录，且本地账本最多保留 128 条。这个有界清理不会改变信封、署名或节点拥有的动作
事实。

## 撰写与发送

撰写会从草稿构造一个 `message.human` 信封，加入新的 `nonce`；回复时再加上
`parents` 引用和一个标明父消息的 `quote`。客户端刻意**不**自行生成事件 ID：ID 由
节点根据规范化内容推导，且节点会拒绝与之不符的 ID，因此客户端的职责是保证唯一性
（`nonce`）与幂等性（`commandId`）。

发送向 `POST /v1/send` 提交 `peerId`、`envelope`、`clientId` 与 `commandId`。
发件箱显示本地状态（`queued` / `sending` / `sent` / `failed`），并另行原样显示节点
自己的 `delivery` 值——本客户端并不知道对端是否真的收到，也不作此声明。重试会复用
原来的 `commandId`，因此节点会合并重复项，而不是创建第二个事件。

排队中的发送会跨刷新保留，并在下一次成功轮询时发出。

## 对端与初始引导

`GET /v1/peers` 填充对端选择器。三种状态被区分对待，因为它们不是同一个问题：

- 目录返回了对端——正常的选择器；
- 目录返回但为空——节点尚未配置对端，文案提示先在节点侧完成配对；
- 目录不可用（较旧的节点）——明确说明这是能力缺口，并提供手动输入对端 ID 作为
  已标注的回退方式。

## 持久化与轮询

`localStorage` 保存节点地址、同步游标、设备 ID、发件箱、未决提交与带时间戳的搁置
标记。搁置会跨刷新保留，但本地账本最多保留最近 128 条、保存 30 天；损坏或过期的
记录只在本机丢弃。这些全部是客户端便利或客户端状态，没有一项是权威。

轮询是增量的、基于游标的：失败时指数退避，标签页重新可见时恢复到正常间隔。第一次
同步会拉完 `hasMore` 指示的所有分页，之后才建立历史基线；这次恢复过程中的任何页面都
不会产生桌面通知。重新连接或 `409` 游标重置会关闭基线并重新完成这次拉取。用户授予
权限后，后续页面只有此前未见过的事件 ID 才可触发通知；通知与投递、呈现、已读、确认和
动作事实保持独立。收到的分页按事件 ID 去重；同一事件以较新的节点快照为准，因为节点的
事实只会向前推进，而在这里发明逐字段合并会让本客户端去裁决它并不拥有的事实。`409`
游标重置被当作指令处理——丢弃游标并从起点拉完所有分页——而不是当作要展示给用户的错误。

当 `/v1/node` 宣布 `capabilities.websocketHints: true` 时，浏览器会在同一 API 基址的
`/v1/live` 建立一个 `ws:`/`wss:` 连接。它只发送 `v1` hello，接受有界的 ready/hint/
ping/pong 词汇，并把每个 hint 当作请求现有 REST 同步的提示。提示在 100 毫秒内合并，
不携带游标或 payload。握手超时为 5 秒，每 15 秒发送心跳，10 秒未收到 pong 触发看门狗；
重连使用等抖动，范围从 500 毫秒到 30 秒上限。帧限制为 4,096 字符，缓冲发送限制为
4 KiB。Socket 断开会关闭通知基线，因此追赶不会重复历史通知；REST 周期校准仍保持。
缺少 capability 或浏览器不支持 WebSocket 时回退到 REST 轮询。`pagehide` 会关闭连接并
暂停工作，`pageshow` 以有界 REST 追赶恢复。

## Fogg 行为模型

- **一次只给一个提示。** 同一时刻只有一个信封处于焦点，决定面板只提供一个主按钮，
  "下一个待决"指向下一个真正需要人的条目。
- **低摩擦的安全选择。** 搁置只需一次点击，且只留在本机。决定需要刻意再做一步，
  因为它是授予或收回权限的那一个。
- **可见的进度。** 顶栏统计已决定、待处理与已搁置的条目并绘制为进度条；搁置被单独
  展示而不计入进度，因为它不是决定。

## About Face 原则

- **直接操作。** 通过点击封面本身选中信封；列表、事实与进度都对同一选择作出反应。
- **即时反馈。** 每次提交都立即显示自身状态，并由 live 区域播报结果。没有任何暗示。
- **不做无法兑现的操作。** 本设计有意偏离"可逆操作"的唯一之处就是决定，因为节点把
  它视为终态；界面会解释这一省略，而不是伪造一个控件。

## 安全姿态

- **对端界面数据是惰性的。** `surfaceRef`、`bodyRef` 与 `parents` 都渲染为引用标记，
  不抓取、不渲染、不执行。
- **没有标记字符串汇聚点。** 本包不包含任何内联标记赋值、相邻标记插入、文档写入
  调用、`eval` 或 `Function` 构造器；每个值都通过 `textContent` 到达 DOM。冒烟检查
  会先剥离注释，再对构建产物进行断言。
- **不可信输入是被收窄的，而不是被"净化"的。** `parseEnvelope` 只复制已知字段，限制
  每个字符串长度，剥离控制字符与双向文本字符，并且**拒绝**署名类型或署名 ID 无法
  识别的信封，而不是把它改标为 `system`。
- **不作传输安全声明。** 本客户端不对 TLS、对端认证或局域网是否安全作任何断言；
  那些属于节点和后续阶段。默认节点地址是回环地址。
- 不依赖网络：没有 CDN、没有网络字体、没有远程资源。

## 主题与可访问性

浅色是纸与墨，色彩只留给信号——朱砂标记唯一需要决定的事项，靛青承载信息，石绿标记
已确定的内容。深色以深海军蓝覆于石墨之上，青色用于交互，琥珀色用于提示注意。两种
主题的角色一致，色彩方向取自中国水墨设色的一般做法，而非任何艺术家的作品。

两种主题都由 `:root` 上的令牌驱动，主题在首次绘制前完成解析。键盘：`j`/`k` 移动、
`n` 下一个待决、`a` 批准、`r` 拒绝、`d` 搁置、`m` 已读、`c` 撰写、`t` 主题、
`Esc` 取消。焦点始终可见，外壳提供跳过链接，并遵循 `prefers-reduced-motion`。

## 运行

```sh
pnpm node:start    # 本机节点（独立包），默认 127.0.0.1:8787
pnpm web:build     # tsc + 静态资源输出到 packages/web/dist
pnpm web:serve     # 在 http://127.0.0.1:4173 提供静态预览
pnpm web:preview   # 先构建，再启动服务
pnpm web:smoke     # 先构建，再断言上述性质
pnpm typecheck     # 根类型检查，包含本包
```

用 `?api=http://host:port` 指向节点。节点默认允许预览来源
（可用 `LINKO_ALLOWED_ORIGINS` 覆盖）。对端配对在节点侧配置
（`LINKO_PEERS_FILE`，TLS 材料为 `LINKO_TLS_KEY` 与 `LINKO_TLS_CERT`）；
本客户端只读取由此得到的对端目录。

## 已知限制与偏差

- **固件数据是预览，不是真实内容的回退。** 没有节点响应时，收件箱显示明确标注的
  固件数据，以便离线评审界面；一旦有节点响应，它们会连同游标一起被丢弃，因此真实
  事件与演示数据绝不会混在一起。
- **节点是另一条工作流。** `POST /v1/send` 与 `GET /v1/peers` 是在本次工作期间加入
  节点包的；早于它们的节点会产生明确的"此节点尚未提供 POST /v1/send"失败，而不是
  静默失败。
- **发送需要节点侧已配置对端。** 默认节点没有配置任何对端，因此撰写界面会正确地
  报告未配对状态。
- **决定是提交，不在离线排队。** 节点不可达时尝试的决定会被记为失败并给出重试，
  而不是悄悄排队、事后假装成功。
- **游标重置后没有持久游标。** 重置会从起点拉完有界分页；本机没有完整日志的缓存。
- **搁置是本机有界状态。** 搁置记录可在 30 天后过期，或在本机账本超过 128 条时被
  淘汰；过期不会改变节点事实。
- **本客户端不是端到端加密客户端。** 群组 E2EE 是独立的里程碑，此处不作任何相反
  的声明。
