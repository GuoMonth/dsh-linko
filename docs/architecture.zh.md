# Linko 架构

[English](architecture.md) | 中文

状态：简洁性评审后的设计基线。单节点本地 MVP 已存在；Peer 容量和密码学声明仍是实现前的关口。

## 小内核

```text
DSH / CLI / 人类收件箱
          │ loopback 本地 API + Origin 白名单
          ▼
一个 TypeScript 节点 + 一个本地 SQLite 数据库
          │ HTTPS REST 恢复 + 已批准的 WSS 在线实时会话（尚未实现）
          ▼
另一个经过认证的节点
```

三个职责足够：**契约与纯状态转移、事务存储、I/O 适配器**。它们是同一进程里的模块，不是微服务。内核根据明确输入做决定，不打开 socket、读取时钟、调用模型或发送通知。宿主校验输入、执行本地事务，再执行队列中的副作用。

提交成功的领域记录才是持久事实来源。SQLite 与事务化 outbox 保存持久状态和待投递任务；REST 游标同步是规范恢复接口。已批准的 WSS 在线实时会话将在相同语义下承载在线信封与回执，但尚未实现。任何传输方式都不定义真相。Peer 游标属于签发它的节点和授权范围，不是全局会话序号。

键、归属、事务边界和失败行为见[数据与状态转移](specs/0005-state-and-storage.zh.md)。

## 分开三张图

- **连接图**：哪些设备能通信。使用普通 IP 和直接认证连接。
- **成员图**：谁能收到哪些消息。由成员和加密规则决定。
- **认知图**：谁认为某个人或 Agent 能帮忙，有什么证据。对有范围的声明计算本地、主观的图投影。

背书不会创造网络可达性，也不会授予权限。找人先查询本地索引，以后再增加有预算的远程扩展。第一对可工作的节点不需要 DHT、共识区块链、全局分数、全局事件总序或图数据库。

## 持久数据、本地操作和派生视图

不可变的签名领域事件记录消息、成员变更和共享声明。SQLite 还保存本地投递任务、游标检查点、阅读状态和动作尝试。这些操作记录可变且私有，不需要全部签名、广播或进入永久账本。

索引和视图生成收件箱、未读数、审计界面和协作者推荐。JSONL 是有版本的导出，不是第二个数据库或事务日志。保留期限、删除、结构迁移和最小去重记录需要明确策略；追加式历史不代表私人正文永久保留。

身份区分主体、设备、Agent/委托。人批准的 Agent 草稿仍保留 Agent 编写来源。签名验证密钥和作者声明，不能证明文字由人亲手输入。

## 网络只留一种基线

Peer 恢复使用基于 TCP 的认证 HTTPS，在线信封与回执使用已批准的 WSS 实时会话。两者共享授权、校验、去重和存储语义；WSS 不可用时仍以 REST 游标同步为规范恢复路径。当前节点已实现 HTTPS 投递与 REST 恢复，尚未实现 WSS。本地浏览器 UI 只连接本机节点，不负责局域网证书和 Peer 发现。即使是 loopback API，也要认证并检查 Origin。

显式配对端点，并通过带外方式验证密钥。mDNS/DNS-SD 仅是可选发现提示；广播包含最少端点和版本信息，不公开能力历史、信任、成员资格或消息正文。正常运行不依赖公共 bootstrap。跨网段发现属于后续部署选项。

路由器和交换机不需要 Linko 专属新特性。IP 可达且端口被允许，是必要前提。手动地址能解决发现失败，不能解决流量被阻止。VLAN ACL、Wi-Fi 客户端隔离和防火墙可能需要管理员配置，rendezvous 节点不能绕过它们。

应用不探测或配置 QoS、SDN、VLAN、巨帧、TSN 或硬件组播。尤其不能把组播侦听当作解决 mDNS 的通用方法：链路本地组播有特殊转发规则。IPv6 是地址族支持；QUIC 和 HTTP/2 是端系统协议，不是新交换机特性。观察到瓶颈后才考虑额外传输。[DNS-SD](https://www.rfc-editor.org/rfc/rfc6763.html)、[mDNS](https://www.rfc-editor.org/rfc/rfc6762.html)、[IGMP snooping 指南](https://www.rfc-editor.org/rfc/rfc4541.html)。

## 消息、群聊与可用性

[信封](specs/0002-message-envelope.zh.md)有简短封面，以及内嵌内容或不可变对象引用。封面已投递、正文已缓存、人已读、动作已批准是独立事实。单有链接不能保证离线可读，接收方必须获得经过校验的本地副本。

第一版群聊目标最多 **500 个成员主体**。初始实现每个主体只有一个活跃设备，多设备需要单独的上限和证据。最简群控制提案是每群一个指定成员变更签名者，普通消息由成员直接交换。这个取舍以及复制管理权的替代方案仍是[群聊规格](specs/0004-group-chat-and-e2ee.zh.md)的决策关口。

先测量连接池里的有界直接扇出，不建立永久全互联。单条消息最多仍有 499 次接收方投递，仅限制人数不是容量测试。群聊、加密离线 mailbox、两万人发现属于不同里程碑。

没有经过授权的在线副本就无法投递，没有保留历史就无法完整追赶。初始设计没有全网中心服务、强制 relay、公共 DHT 或自动选主。

## 加密与 UI 边界

局域网可达不等于信任。TLS 认证 Peer 会话，消息层 E2EE 保护经过非收件方存储的内容。在发送真实敏感内容前，必须先设计点对点和群聊密钥生命周期。MLS 是群加密候选，不是已选依赖，也不负责消息投递。禁止静默回退到明文。

有意义的封面、正文和 surface 数据按受众加密，relay 只需要最少路由元数据。已缓存明文不能被召回。移除成员保护的是发送方采用变更后、以新密钥加密的消息，不能追溯保护仍使用旧状态的离线发送者。

人类卡片渲染已知组件，不执行 Peer 任意 HTML/JavaScript。Agent 输入、UI 动作和远端风险标签都不能授予权限。接收方检查委托、当前策略、payload 摘要、成员版本、过期和动作 ID。

## 验证与扩展规则

先写明确转移表、类型化命令/事件、SQL 约束和崩溃/乱序/重复轨迹。有实现后，用独立模型做属性测试。投递/游标竞争、成员变更串行化上线前，用小型 TLA+/TLC 模型检查。Lean 4 留给具体的无界证明义务，不作为运行依赖，也不代替存储和网络测试。见 [ADR 0008](decisions/0008-minimal-kernel-and-verification.zh.md)。

Rust/WASM 保留为针对可测确定性计算的实验，不负责 socket，也不自研密码学。WebTransport 与 QUIC 是延期实验。Linko 不增加应用层路由器或正文洪泛。Merkle 树、Gossip、丰富 UI 适配器、分布式推荐算法进入基线前，都需要已观察的瓶颈、明确范围和验收测试。
