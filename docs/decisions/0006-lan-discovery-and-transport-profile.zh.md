# 0006 局域网发现与传输配置档

状态：设计阶段已接受。

## 决策

Linko 以普通 IP 网络作为基础。基础传输配置档是 HTTP 请求响应加基于 TCP 的 WebSocket。在本地链路上，优先使用 mDNS 上的 DNS-SD 做零配置发现，并以显式配对和配置好的 rendezvous Peer 作为降级方式。

IPv6、HTTP/2、QUIC、WebTransport 和 libp2p 传输属于可选增强配置档。节点协商能力；增强配置档不可用时，必须回退到基础配置档。

Linko 的普通运行不要求修改路由器、交换机、VLAN、组播侦听、QoS、802.1X 或防火墙。网络设备可以改善可达性、分区或优先级，但属于部署优化，不是协议依赖。

应用层转发必须有边界并且按需选择。已知接收端点时，直接消息优先直接投递。发现和反熵同步可以使用有边界的 Peer 交换或 pub/sub。在线发现不能隐式触发消息正文广播。

## 理由

Wi-Fi 隔离、VLAN、操作系统、VPN 和企业网络的局域网行为并不一致。如果要求新的交换机或路由器特性，产品会在第一次安装时就失效。基于能力的增强可以提高延迟和规模上限，同时保留可部署的基础回退。

## 后果

- 测试必须覆盖 mDNS 不可用、IP 变化、网络分段和普通 TCP。
- Peer 身份独立于端点地址保持稳定。
- 增强传输适配器可以在不改变消息语义的情况下增加。
- 跳数限制是安全预算，不能替代去重、扇出、字节预算和背压。
