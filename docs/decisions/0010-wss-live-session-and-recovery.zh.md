# 0010 WSS 在线实时会话与持久恢复

[English](0010-wss-live-session-and-recovery.md) | 中文

状态：2026 年传输方向已接受；WSS 实现与验收证据仍待完成。

## 决策

配对 Peer 之间使用基于 TLS 的 WebSocket（WSS）作为在线实时会话。实时信封与回执沿用 REST 投递的授权、校验、去重和存储规则。这取代 [ADR 0005](0005-local-node-rest-sync-websocket.zh.md) 与 [ADR 0006](0006-lan-discovery-and-transport-profile.zh.md) 中 WebSocket 只做提示的定位；本地节点、恢复与信任边界继续有效。

SQLite 拥有持久化的已接受事件和本地运行状态。事务化 outbox 拥有待投递任务，并负责 socket 断开与进程重启后的重试。REST 游标同步仍是断线、缺口和追赶的规范恢复契约。socket 写入成功、ping/pong 或连接握手都不代表持久接受，也不能推进恢复检查点。投递确认必须等待接收事务提交；客户端原子保存恢复批次与检查点。

WSS 会话必须具备经过认证的 Peer 范围、有界帧和队列、背压、存活检查与重连退避。重连时通过 REST 从最后的持久检查点恢复；投递结果不确定时，outbox 使用同一事件身份重试。实时与恢复流量共享去重规则，重连不能增加重复收件箱记录或重复已批准动作。

WebTransport 与 QUIC 仍是延期实验，没有发布承诺。只有出现可测瓶颈、限定实验范围，并证明相同的持久恢复与认证 TCP 回退仍然有效后，才重新考虑。

mDNS/DNS-SD 仅是可选发现提示。只广播最少端点与版本信息；广播不认证 Peer，也不授予成员资格或权限。发现不可用时，仍可显式配对并进行带外核验。

Linko 不增加应用层路由器、转发中继网络或正文洪泛。已知接收方使用经过认证的直接单播；群投递使用有界直接扇出。路由器和交换机提供普通 IP 可达性与部署控制，不承载 Linko 路由逻辑。发现、查询扩展和同步继续使用独立预算。

## 理由

实时会话支持及时的双向交换，崩溃恢复仍由已有持久状态模型负责。SQLite、outbox 与 REST 保持权威边界，避免引入第二套队列或第二种送达定义。选定的 TCP/TLS 基线允许项目先验证一种实时会话设计，再考虑额外传输。

## 实现边界

当前节点已实现配对 HTTPS 投递、证书指纹固定、Bearer 认证、SQLite outbox 与 REST 恢复，尚未实现 WSS 在线实时会话。本决策选定下一步传输方向，不是 WSS、发现、签名、E2EE、群投递或容量的发布证据。

节点另外提供一个仅限回环地址的 `ws://.../v1/live` 通道，供本地浏览器 UI 接收失效提示。它只携带有边界的失效提示，不拥有 Peer 权限、消息正文、队列或恢复游标，UI 始终回到 REST 同步。这个本地唤醒通道是已经实现的展示辅助，并不是本记录选择的配对 Peer WSS 会话。

本地浏览器、CLI 与 DSH companion bridge 继续使用本地 API。Peer 会话决策不要求这些客户端管理 Peer socket 或发现。

## 后果与验收

- WSS 断开或不可用时，REST 恢复仍然可用；不能弱化认证或回退为明文。
- 证明经过认证的双向 WSS 投递与回执、未授权 Peer 拒绝和有界过载行为。
- 覆盖半开会话、确认丢失、实时/恢复事件重复、重连风暴，以及持久提交前后的进程崩溃。
- 证明 outbox 重试与 REST 追赶能够收敛，不产生重复收件箱消息或重复动作副作用。
- 在关闭 mDNS、显式配置直接端点时验证运行；不能依赖应用层路由或正文广播。
- 在将 WSS 描述为已实现前，把证据记录到 [Roadmap 阶段 2](../../ROADMAP.zh.md)。
