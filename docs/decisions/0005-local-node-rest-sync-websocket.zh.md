# 0005 本地节点、REST 同步与 WebSocket 加速

状态：设计阶段已接受。

## 决策

每个 Linko 安装实例都是一个本地节点，拥有自己的 SQLite 事件日志、发件箱、收件箱、回执、投影和 Peer 会话。CLI、Web UI 和 DeepSeek Harness 集成使用本地节点 API。

基于游标的 REST 同步是恢复、历史读取和状态收敛的事实来源。WebSocket 是事件提示、小型实时事件、回执和 UI 响应的加速通道。WebSocket 连接不能成为消息的唯一副本，也不能替代基于游标的拉取。

投递采用至少一次语义，并由接收方去重。发送方先持久化再发送；接收方先持久化再报告 `delivered`。已读和执行状态属于独立事件或投影。

## 理由

这种组合同时获得了 HTTP 同步的运维韧性和聊天需要的低延迟。浏览器、CLI 或 Peer 在 socket 断开、设备休眠或进程重启后仍能继续工作，也使持久协议不绑定某个 WebSocket 库。

## 后果

- 运行时需要本地守护进程或等价的长期运行进程。
- 每条 Peer 会话需要游标、协议版本、能力集合和有界队列。
- 实现必须支持幂等、可安全重放的事件、退避和游标恢复。
- 只支持推送、不支持拉取恢复的实现不符合要求。
