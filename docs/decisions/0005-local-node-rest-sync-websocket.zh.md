# 0005 本地节点、REST 同步与 WebSocket 提示

[English](0005-local-node-rest-sync-websocket.md) | 中文

状态：设计阶段已接受。

## 决策

每个安装实例运行一个本地 Linko 节点和一个 SQLite 数据库。CLI、Web UI 和 DeepSeek Harness 集成使用本地 API。

持久化的已接受领域事件和明确声明的本地运行记录是事实来源。REST 是规范的恢复与有范围同步接口。WebSocket 是可选唤醒提示通道，只能通知状态可能变化，不能确认游标，也不能替代拉取恢复。

投递采用至少一次，并在接收方验证和去重。发送方在发送前提交事件和投递任务。接收方在报告接受或送达前，提交事件、去重结果、收件箱投影和检查点。已读、确认、审批和动作仍是独立状态维度。

## 理由

小型本地节点避免 UI、CLI 和 Agent 集成各自实现发现、重试、策略和持久化。拉取恢复能够承受 socket 断开、设备休眠和进程重启。把 WebSocket 当作优化，避免把存活性误当持久性。

## 后果

- 一个进程拥有本地事务边界；reducer、存储和 I/O 由模块分开。
- 每个 Peer 会话都有认证范围、协议版本、日志纪元、游标和有界队列。
- 响应丢失时重试同一事件，不创建新事件。
- 任意 mailbox 或 relay 都只是具有明确保留与元数据暴露规则的可用性辅助，不是全局真相。
