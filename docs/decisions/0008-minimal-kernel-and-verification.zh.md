# 0008 最小内核与验证边界

[English](0008-minimal-kernel-and-verification.md) | 中文

状态：设计阶段已接受。

## 决策

第一版运行时是一个 TypeScript 节点和一个 SQLite 数据库。核心是纯 command/event reducer，加上明确的事务适配器。持久领域事件、本地运行记录和可重建投影分属不同类别。

第一版验证栈为：

1. 类型化状态转移表和 SQL 约束；
2. 带显式策略与时钟输入、与语言无关的 fixture；
3. 性质/模型测试以及崩溃、乱序轨迹；
4. 用小型 TLA+/TLC 模型检查并发和活性问题。

Lean 4 只有在存在具体定理或反例时，才允许作为有时间边界的离线 falsification spike。它不进入运行时、不成为 CI 必装工具，也不作为阶段闸门。Rust/WASM 同样只有在测量证明存在确定性工作负载收益，并有跨运行时 fixture 时才引入。

## 理由

这里最危险的是状态和恢复失败，而不是传输不够新奇。纯 reducer 让回放和矛盾变得可见；SQLite 提供成熟事务边界；fixture 让边界可测试。TLA+ 更适合探索交错执行，Lean 适合在简化后仍然存在明确代数证明目标时使用。

形式模型可以证明模型的性质，也可以推翻假设；它不能证明一个尚未实现的网络、存储配置或密码库真的拥有这些性质。

## 后果

- 基线不拆微服务、不用图数据库、DHT、区块链共识，也不建立全局事件顺序。
- 先写合并规则和冲突行为，再实现。
- 单元测试通过时，崩溃测试仍可能失败；持久性声明需要两者。
- 后续可以加入 WASM 或形式化产物而不改变消息契约，但不承诺未来工具链。
