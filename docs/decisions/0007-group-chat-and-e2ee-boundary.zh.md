# 0007 群聊容量与 E2EE 边界

[English](0007-group-chat-and-e2ee-boundary.md) | 中文

状态：提议配置档；成员签发者仍是决策闸门。

## 决策

第一版群配置档最多 500 个活跃成员主体，初期每主体允许一台活跃设备。只有通过群内指定成员签发者、签名版本和父哈希串行化成员变更，人数上限才可强制。消息可以通过有界直接扇出投递；群不要求全连接。

传输加密和消息层 E2EE 分开。MLS 是候选协议，不是已选实现，也不是投递系统。受保护群内容不能静默回退明文。移除与离线行为必须按密钥纪元及发送者是否采用新密钥说明，不能承诺追溯保密。

已读状态默认私有。共享回执有边界，只发给作者或指定聚合方，不按每条消息、每台设备向全群广播。

## 理由

硬上限需要串行化点。选择一个群内签发者，比假设分区中的多个管理员可以用本地检查强制全局人数更简单、更诚实。它保留点对点消息传输，同时承认成员变更需要协调。

## 后果

- 签发者不可用时，现有成员仍可通信；成员变更等待。
- 签发者丢失、权限移交、备份、冲突隔离和多设备需要后续决策。
- 群投递和 E2EE 分成不同里程碑和报告。
- 500 人产品测试不是容量或安全证明。
