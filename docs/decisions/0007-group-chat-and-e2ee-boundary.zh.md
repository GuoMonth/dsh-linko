# 0007 群聊容量与端到端加密边界

状态：设计阶段已接受。

## 决策

第一版 Linko 群聊配置档上限为 500 名成员，包含人、Agent 和服务身份。群聊不建立成员之间的全互联连接，而是使用与一对一消息相同的事件日志和游标同步，并配合选定的投递路径和有边界的扇出。

传输加密和消息层端到端加密是两个独立要求。在消息层密钥完成建立、轮换、移除和恢复并通过测试之前，Linko 不能宣称群聊内容是端到端加密。异步群组加密的主要候选是 MLS；项目使用成熟实现，不自行发明密码协议。

Relay 和 mailbox 可以保存加密信封。成员和设备变更属于签名事件。被移除的设备不能解密未来受保护消息，新成员默认不会获得历史明文。

## 理由

500 名成员为第一版提供了有用的协作空间，同时把扇出、回执、通知和密钥管理测试控制在可测范围内。这个上限是产品配置档，不是对局域网原始带宽的判断。

## 后果

- 群聊容量、投递和密钥轮换证据成为阶段门槛。
- 只有传输层加密的原型必须明确描述为传输加密。
- 群聊 UI 和 Agent 策略必须展示成员、作者和审批状态。
- 更大规模的房间需要新的配置档、测量和明确的协议工作。
