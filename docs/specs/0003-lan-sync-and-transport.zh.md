# 0003 局域网同步与传输

[English](0003-lan-sync-and-transport.md) | 中文

状态：草案；2026 年传输方向记录于 [ADR 0010](../decisions/0010-wss-live-session-and-recovery.zh.md)。

## 基线

一个本地节点拥有一个 SQLite 数据库。DSH、人类收件箱和 CLI 适配器使用带明确 Origin 白名单的本地 API。节点恢复使用 TCP 上的 HTTPS；已批准的 WSS 会话用于在线信封与回执，但尚未实现。REST 游标同步与 SQLite/outbox 仍是规范恢复路径。长轮询使用同一有界同步 API。本地 UI 不负责发现和连接所有远端 Peer。loopback MVP 不提供 Peer 认证，绑定到 loopback 之外前必须完成认证。

可单播的 IP 路径和允许的端口是前提，不要求 Linko 专用路由器/交换机特性。手动配对只能解决发现失败，不能绕过防火墙、VLAN ACL 或 Wi-Fi 客户端隔离。WebTransport 与 QUIC 推迟为实验，直到出现可测瓶颈并有界回退测试。

## 配对与发现

先用明确端点和带外密钥核验。端点变化不改变 Peer 身份。mDNS/DNS-SD 是本地链路上的可选提示，与显式配对并列，不是协议假设。只广播最小端点/版本提示；发现不能授予信任，也不广播消息或能力历史。

跨网段可后续增加配置的 rendezvous 和有界 Peer 交换，不能绕过被阻断的 IP 路径。基线不包含 DHT、强制公共引导或全网洪泛。发现、任务查询扩展、状态同步分别设置预算。

## 拉取契约

持久提交记录是事实；REST 是恢复接口：

```text
GET  /v1/node
GET  /v1/sync?cursor=...&wait=...
POST /v1/envelopes
GET  /v1/objects/{hash}
POST /v1/receipts
```

这些是概念端点，不是冻结的线协议。本地管理配置档检查回环 Host 和 Origin；双节点非 loopback 配置档通过独立 Peer 监听器认证，并把请求限制到已配置的 Peer。POST 按验证后的事件身份去重。同步返回有界批次和不透明下一 token，绑定签发 Peer、授权范围和日志纪元。游标不是全局消息顺序。批次和下一检查点原子保存。

MVP 的线形状是：`events[]` 每一项直接包含信封字段，并带 `eventId`、`cursor` 和同级的 `facts` 对象。facts 是投影，不是不可变信封的一部分。`POST /v1/receipts` 接受 `{ eventId, deviceId?, state, actionId? }`，其中 `state` 可以是 `presented`、`read`、`acknowledged`、`approved` 或 `rejected`。本里程碑中批准和拒绝都是终态回执，不会启动执行。真实节点响应必须在跨包 contract fixture 中经过 Web parser。

双节点投递配置档增加三个小接口：

```text
GET  /v1/peers
POST /v1/send                 { peerId, envelope, clientId, commandId }
GET  /v1/outbox
POST /v1/peer/events          （仅 HTTPS Peer 监听器）
```

`/v1/send` 在同一事务中提交本地信封和出站队列。重试必须复用 `clientId` 与 `commandId`；接收方以至少一次方式保存同一事件身份，并在适当时返回 duplicate。发送方有有限的重试预算，耗尽后显示 `abandoned`，不会无限重试；显式使用新的 command 可以让同一事件重新排队。Peer 监听器不提供本地管理路由，要求配置的 Bearer 密钥；发送方检查配置的证书指纹。本地管理监听器保持在回环地址。Peer 目录只暴露标签，不暴露密钥。

token 过期或日志纪元变化触发明确、有界的快照加增量恢复。协议不兼容返回版本错误；快照不能修复协议不兼容。缺依赖进入有界待处理状态。见[数据与状态](0005-state-and-storage.zh.md)。

第一版握手使用封闭词汇：协议/schema 版本、Peer 身份证明、日志纪元、端点提示、帧/批次/对象大小上限，以及可选群组/加密配置档 ID。WSS 在线会话必须保持这些授权和大小边界。必需版本或加密套件不支持时明确失败。WSS 丢失或不可用时回退到 REST 游标恢复；必需加密不能回退明文。

## WSS 在线实时会话

已批准的 WSS 通道在完成 Peer 认证后承载在线信封与回执。它不拥有持久事实，也不推进恢复游标：SQLite、outbox 与 REST 游标同步仍是规范路径。确认丢失、实时/恢复事件重复和重连都复用同一事件身份与去重规则。当前节点尚未实现此会话；不能把本规格描述为已上线行为。

必须有 ping/pong 或等价存活检测、空闲超时、帧和队列上限、有界并发请求、优雅关闭、带抖动的指数重连退避。为控制流量预留容量，避免正文拉取饿死恢复流程。

## 投递与可用性

发送前持久化事件和投递任务。报告送达前提交验证后的接收/去重/收件箱状态。响应丢失时重试同一事件。这是至少一次传输加本地幂等写入，不是外部副作用恰好一次。

发送方、接收缓存或显式授权 mailbox 必须有在线副本才能拉取。所有合格持有者都离线或删掉内容时，显示延迟/不可用；不能凭空承诺离线投递。加密 mailbox 属于后续里程碑，需要配额、保留、元数据暴露和删除规则。

初期使用简单游标拉取与明确缺依赖恢复即可。参与者序号区间、摘要、Peer 交换和选择性复制须作为有测量证据的扩展；不预设 Merkle 同步。

## 边界与证据

传输实现前必须确定连接、队列、批次、重试、待处理依赖、对象的具体数值上限及过载错误。跳数上限不是风暴控制的替代品。已知接收方使用单播；群扇出使用有界连接池。

按用户要求，目标部署边界仍保留最多 20,000 名参与者。这是设计约束，不是已支持容量：不能全连接，也不能全网广播正文。发布容量声明需要逐步完成 100/1,000/10,000/20,000 模拟发现测试及代表性真实有线/Wi-Fi 证据；群流量单独测试。

验收轨迹覆盖普通 TCP、关闭 mDNS、IP 变化、休眠、防火墙拒绝、半开会话、重连风暴、响应丢失、旧游标、正文缺失和重启恢复。两个节点直接互通是第一道闸门。
