# 0004 群聊容量与端到端加密

[English](0004-group-chat-and-e2ee.md) | 中文

状态：草案。

## 范围

第一版 Linko 群聊配置档最多支持 500 名成员，包括人、Agent 和服务身份。这是初始配置档的产品与协议上限，不代表局域网无法承载更多流量。超过上限的成员变更必须被客户端拒绝。

## 群聊模型

群聊是一个带有稳定群组 ID、成员事件、每个发送者序号和策略的事件流。策略规定谁可以邀请、移除、发言、请求上下文和审批 Agent 动作。群组事件日志按需复制；只有在成员和可见性检查通过后，成员才能接收面向群组的事件。

协议不会为每个成员创建 500 条全互联 WebSocket 连接。节点维护有限的 Peer 会话，并使用直接投递、选定的 relay 或有边界的主题网格。群聊扇出属于投递问题，群聊语义仍然保留在事件日志中。

UI 必须区分：

- 人编写的消息；
- 受委托 Agent 消息；
- 自主 Agent 消息；
- 系统成员、回执或同步事件。

群里的 Agent 消息带有意图、范围、过期时间和动作策略。群管理员可以要求 Agent 发言、共享上下文、邀请成员和扩大扇出前经过人工审批。

## 加密边界

传输加密保护单条 Peer 会话，但不能保护 mailbox 或 relay 中的消息。消息正文必须在消息层先加密，然后才能交给不属于目标收件人的 relay 存储。

Linko 不自行发明密码协议。设计阶段评估成熟的异步群组协议，并以 IETF Messaging Layer Security（MLS）作为群聊配置档的主要候选。评估必须覆盖成员变更、离线成员、设备增删、前向保密、事后入侵安全、密钥恢复和实现可用性。

在群组消息层加密完成并通过测试前，产品只能描述为“传输过程中经过认证和加密”，不能称为端到端加密。无法建立所需密钥的群组必须对受保护内容安全失败，不能静默降级。

## 密钥与成员事件

密钥、成员和设备变更都是带签名的事件，并保留作者和生效时间。移除设备后，该设备不能解密未来的受保护消息。新成员加入后，不能自动获得历史明文，除非有明确的历史共享决定。

封面可以暴露投递和通知所需的最少元数据。正文、证据和 UI surface 根据群组策略加密或通过能力引用保护。

## 容量证据

500 人配置档发布前，至少测试 2、50、200 和 500 名成员，并覆盖：

- 加入、离开、邀请和设备替换；
- 离线追赶和重连；
- 消息扇出和去重；
- 回执和通知量；
- 密钥轮换和密钥安装失败；
- 一个或多个 relay 节点不可用。

测试报告必须包含 p95 投递延迟、每成员字节数、待处理队列大小、重复事件率和恢复时间。
