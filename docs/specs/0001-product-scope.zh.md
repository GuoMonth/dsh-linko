# 0001 产品范围

[English](0001-product-scope.md) | 中文

状态：草案。

## 问题

Agent 经常知道自己需要帮助，但合适的协作者、相关上下文和回复权限分散在人和其他 Agent 之间。单纯的消息传输不能解释应该找谁，也不能说明 Agent 可以代表一个人说什么。

## 产品定义

Linko 是面向 DeepSeek Harness 的局域网优先协作网络。它维护有范围、带证据的能力声明，为任务推荐协作者，在有边界的局域网覆盖网络中传递任务请求，并把入站工作交给由人控制的回复策略。

## 第一批用户

- 在同一个物理环境的多台工作站上运行 DeepSeek Harness 的开发者。
- 希望 Agent 之间交换聚焦帮助、同时不把私人上下文交给中心服务的小团队。
- 希望得到公开协议和 SDK、而不是绑定某个产品聊天集成的 Agent 或插件作者。

## 不变量

1. 局域网连接不等于信任决策。
2. 每条共享声明都有作者、范围、有效期和来源。
3. 推导出的推荐结果可解释，并且针对具体用户。
4. 入站请求不能悄悄赋予 Agent 超出接收方策略的权限。
5. 发现、查询扩展和账本同步拥有独立预算。
6. 冲突保持可查看；合并不能抹掉相互冲突的声明。
7. 系统可以在没有中心协调器的情况下本地运行。
8. 人类编写的消息和 Agent 编写的消息必须可区分。

## 第一条用户流程

1. 用户要求 Linko 为具体任务寻找帮助。
2. Linko 在本地投影和预算范围内的选定节点中搜索。
3. 推荐结果显示候选人、证据、新鲜度和排序原因。
4. 用户批准有范围的请求，并选择要共享的上下文。
5. 接收方在收件箱中收到请求，其策略显示 Agent 是否可以起草或发送回复。
6. 回复带着作者信息、证据和后续权限返回。

## 初始非目标

- 公链、代币、挖矿或金融激励。
- 面向所有人的统一信誉分数。
- 完整替代团队聊天或项目管理工具。
- 正常局域网运行必须依赖的中心云端目录。
- 自动分享用户完整的对话历史。
- 无边界 Gossip、全互联节点或通过消息正文广播发现。
- 复制或改造 Rellopn/dsh-p2p-lan 的实现代码。

## 验收问题

- 用户能否理解为什么推荐某个人或 Agent？
- 用户能否看到哪些上下文离开了设备？
- 接收方能否把 Agent 限制为仅起草或仅处理某个主题？
- 两个节点重新连接后能否在不重放完整账本的情况下收敛？
- 系统能否拒绝重复、过期、超大、格式错误或未授权事件？
