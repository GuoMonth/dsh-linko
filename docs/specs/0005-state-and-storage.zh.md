# 0005 数据与状态转移

[English](0005-state-and-storage.md) | 中文

状态：设计契约草案。物理 schema、规范编码和具体预算仍是实现前的闸门。

## 持久事实与运行状态

使用一个 SQLite 数据库。保留四类领域/存储概念：不可变签名事件 `event`、内容寻址对象 `object`、本地信任的 `peer`、有范围的 `sync_checkpoint`。这是概念，不是强制只能有四张表。

事件包含 schema 版本、参与者/设备、参与者序号、类型、受众/范围、因果引用、payload 哈希和签名。在 fixture 可执行之前，必须确定规范编码和哈希域。主体与其设备分开；委托把 Agent 与授权主体关联，但不改变作者类型。

节点还需要持久化且可变的本地运行记录：投递任务、审批/执行尝试、私有已读状态、通知任务和对象可用性。它们不能都从共享事件恢复：私有审批、重试结果和用户忽略操作是本地事实。收件箱、成员视图和协作者索引属于可重建投影。JSONL 是有版本的导出，不是第二个事务存储。

内容寻址正文不可变；信封中的引用不能证明接收方已持有正文。支持删除之前，必须同时确定内容保留和最小去重记录的保留策略。

## 身份、去重与合并

三种标识解决不同的问题：

- `event_id`：规定的规范化未签名事件 payload 的哈希，包含参与者、范围和序号；签名绑定该 payload。
- `command_id`：客户端重试标识，范围包含客户端、操作和 payload 摘要；一个本地命令事务最多产生一个事件。
- `attempt_id`：一次传输或执行尝试。重试不能产生同一事件的新副本。

相同事件 ID 和规范字节是重复。相同 ID 下出现不同字节，或同一参与者序号对应不同 payload，属于冲突。保留证据并隔离受影响的参与者序号范围；不能按“先到先得”静默选胜者。相信重复声明前仍须完成密码学验证。

不同字段没有万能合并函数。规则如下：

| 数据 | 合并规则 |
| --- | --- |
| 不可变消息与独立认知声明 | 按事件 ID 做集合并集；并发消息共存 |
| 同一发布者的声明更新/撤销 | 显式发布者序号与 supersedes 引用；缺口保留待处理 |
| 不同人的看法 | 保留独立声明；不覆盖，不产生全局分数 |
| 群成员/密钥纪元 | 选定授权主体/协议的有效父版本链；不采用最后写入获胜 |
| 私有运行记录 | 本地事务；不在网络中合并 |
| 共享已读回执 | 按设备记录明确事件覆盖范围；覆盖集合并集、有界批次 |

投影为 `project(validatedEventSet, policyVersion, evaluationTime)`。事件集合与显式输入相同时，结果与到达顺序无关。先解析因果依赖，再投影依赖事件。缺依赖时等待；授权链冲突时阻止其后继并提示修复。不能从墙上时钟或本地插入顺序推断因果先后。

过期改变当前适用性，不改变历史作者。已撤销声明从当前推荐中排除，但可保留来源。撤销不追溯抹除有效历史。密钥泄露恢复及追溯失效需要单独明确策略。不同信任策略可以从相同声明产生不同推荐。

## 分离状态维度

| 维度 | 状态/转移 | 含义 |
| --- | --- | --- |
| 发送任务 | queued → sending → confirmed；sending → retry_wait → sending；rejected/abandoned 终止 | 响应丢失表示不确定；重试同一事件 |
| 接收存储 | unknown → accepted；dependency_pending → usable | accepted 表示已认证、持久存储或验证过的重复；缺依赖不能授权执行 |
| 接收收件箱 | absent → delivered | delivered 表示已提交并对有权接收方的收件箱可用；正文是否可用另计 |
| 人类展示 | unseen → presented；查看/显式标记 → read | 按设备记录；通知独立；显式标记不必渲染正文 |
| 确认 | absent → acknowledged | 人或有权 Agent 的明确确认；不能从已读推断 |
| 执行尝试 | requested → awaiting_approval → approved → executing → succeeded/failed/uncertain | 策略可拒绝或使待办过期；执行中崩溃可能结果不确定 |
| 成员提议 | proposed → rejected 或 committed | 激活取决于有效成员版本和所需密钥 |
| 委托 | granted → active → expired/revoked | 执行开始时重验；过期不能撤回已完成的外部副作用 |

节点可以原子地使事件同时 accepted 和 delivered。这些词是观察事实，不是通用六步生命周期。Agent 可以处理未读消息；阅读不能批准执行。聚合展示可以说“已在一台设备阅读”，没有证据就不能说“所有设备已读”。

私有已读标记使用本地会话插入序号。共享回执必须携带明确事件 ID 或验证过的参与者序号覆盖范围，不能使用其他节点的本地序号。迟到消息获得新的本地位置，仍未读。已移除设备不能发布新的有效已读事实；以前有效的记录保留为历史。

审批绑定消息摘要、动作 ID、受众、授权和策略版本。执行前立即复核当前权限。外部调用过程中取消/过期不能保证回滚。不确定副作用的重试必须有下游幂等契约，或由人核对。

## 游标作用域

同步 token 属于签发 Peer、授权流/范围和 `log_epoch`。其中的本地追加位置既不是参与者序号，也不是全局会话顺序。每次拉取都重新检查权限。

日志重建或不兼容的保留边界使旧 token 失效。返回明确的重置要求，走有界、授权的快照加增量恢复；不能用空成功响应静默跳过数据。客户端在同一事务内保存接收批次和下一检查点。WSS 实时流量不能推进恢复检查点；只有规范 REST 游标路径在持久保存后才能推进它。

## 验证与事务边界

解析前拒绝超大帧；随后检查 schema/版本、规范哈希、签名、范围/权限、依赖/版本一致性和去重。合法签名同样受速率和字节限制。结构有效但缺依赖的事件进入有界待处理存储，不能陷入无界拒绝/重试循环。

一个接收事务内：追加验证事件或重复结果、更新去重和收件箱/投影状态、排队回执、提交对应检查点。持久提交后才报告 accepted/delivered。参考持久配置候选为 SQLite WAL 加 `synchronous=FULL`；宣称持久性前，必须在支持的平台上进行崩溃测试。

一个发送事务内：保存命令幂等记录、事件和投递任务。提交后发送，再记录响应。发送后崩溃只造成重复重试，不能创造新事件。重启后，未完成发送重试；executing 动作转为 uncertain；部分对象校验完成前保持不可用。

审批和执行任务原子记录。通知、socket、对象拉取和外部工具在事务外运行，完成结果另行记录；数据库事务不能让远端副作用天然恰好一次。

## 不变量与 fixture

1. 一个已接受事件 ID 绑定唯一规范 payload。
2. 回执与检查点不确认未提交数据。
3. 重复网络投递只生成一个收件箱条目。
4. 投递/阅读/确认不授予执行权限。
5. 缺失或冲突的成员/密钥依赖不能授权执行。
6. 私有可变状态不被误当成签名公共事实复制。
7. 相同事件集合、策略版本和评估时间产生相同领域投影。
8. 观察到撤销后阻止新副作用；离线节点不能执行它尚不知道的撤销。

未来每个 fixture 包含 schema 版本、初始状态、显式时间/策略输入、有序命令或到达排列、预期事件/投影和错误码。格式与实现语言无关；预期结果不能由实现自动生成。

必要轨迹包括重复/冲突 ID、参与者双签、缺父事件、提交前后及发送后崩溃、旧纪元游标、迟到未读事件、审批过期、不确定工具执行、人数上限处的并发成员变化、旧密钥和损坏/缺失正文。通过这些轨迹是未来实现证据，不是本文件已经完成的承诺。
