# 0007 群组成员状态机

[English](0007-group-membership-state-machine.md) | 中文

状态：已实现的 Reducer 内核；第一版群组配置的发布证据仍在计划中。只定义成员状态，不定义消息加密或网络投递。

## 配置档与授权者

一个群组最多有 500 个活跃成员主体。第一版每个主体只有一台活跃设备，因此每个活跃主体恰好贡献一个设备身份。每个群组有一个成员授权者，以主体和设备二元组标识；在本配置档中授权者身份与活跃名单分离，不能被添加为成员。授权移交、自动选举、多活跃设备和故障接管不在本配置档内。

初始状态包含群组标识、授权者、可选初始名单、序号 `0` 和空父哈希。名单必须保证每个主体只有一台设备，且不能超过配置上限。测试配置可以使用更低上限，但任何状态都不能把上限配置为 500 以上。

## 签名提交形状

提交是不可变的、具有签名版本形状的输入：

- `groupId`、正整数 `sequence`、当且仅当序号为 1 时才为 null 的 `parentHash` 以及 `commitHash`；
- 包含 `principalId` 和 `deviceId` 的 `signer`；
- 按顺序排列的成员操作列表；以及
- 非空的 `signature`。

Reducer 暴露规范化的无签名 JSON 字节。调用方必须注入签名和哈希校验器；没有校验器时 Reducer 会安全拒绝。校验器可以返回 `verified`、`invalid` 或 `unavailable`。授权者密钥暂不可用是等待条件，不是拒绝。

## 状态转移

有效提交必须由当前授权者签名，序号为 `current + 1`，并把当前头哈希作为父哈希。操作按列表顺序原子执行：

- `add` 插入尚未活跃的主体和设备；
- `remove` 移除活跃主体，可选地校验其当前设备；以及
- `replace` 根据预期旧设备把一个主体切换到新设备。

本配置档不能移除或替换授权者成员，因为授权移交是单独的决策。若提交会使活跃主体超过配置上限，则以 `over-cap` 拒绝，不会暴露部分操作。失败操作、过期设备预期、重复主体或替换为同一设备都以 `invalid-transition` 拒绝。

## 连续性、重放与冲突

Reducer 只沿连续的父哈希和序号链推进。父提交尚未到达时，子提交以 `missing-parent` 原因保留为 `pending`；父提交应用后，按序号和哈希顺序重试连续的待处理后代。相同签名字节再次应用返回 `duplicate`，历史中只保留一条已接受记录。

已接受 `commitHash` 下出现不同载荷或签名、同一序号出现不同哈希、使用已知非头父提交，或成为隔离提交的后代，都会以冲突原因返回 `quarantined`。隔离会保留未接受输入和证据，不会静默选择分支。已接受的头和成员投影保持不变，状态会暴露包含分歧序号、已接受哈希和冲突哈希的 `blocked` 记录。处于阻塞时，新的成员提交以 `conflict-blocked` 拒绝，直到存在显式修复操作。格式错误、错误群组、无效签名或未授权签名者返回 `rejected`，且不会推进头。

批量重放会在归约前按序号和哈希排序。成员、已接受记录、待处理记录、隔离记录和阻塞证据保持稳定顺序，因此固定提交集合与校验结果在不同到达顺序下产生相同状态。后到的冲突分支不能改写已接受的头；其提交会保持隔离，待处理后代也会被隔离，阻塞可见期间不能推进新的依赖成员状态的工作。

## 可观察结果

每次应用都返回结果状态、提交哈希、`kind`/`status`、可选原因，以及本次推进的哈希。调用方必须显式处理这些结果：

| 结果 | 含义 |
| --- | --- |
| `applied` | 提交成为连续链头；也可能释放待处理后代。 |
| `duplicate` | 再次看到完全相同的已接受提交。 |
| `pending` + `missing-parent` | 输入结构有效，但所需链尚未出现。 |
| `pending` + `signer-unavailable` | 已知授权者身份，但注入的校验边界当前无法验证其签名。 |
| `quarantined` | 输入与已接受或已隔离链冲突，并被保留以便修复。 |
| `rejected` + `conflict-blocked` | 已有授权历史冲突，新的成员推进等待显式修复。 |
| `rejected` | 输入格式错误、未授权、密码学无效，或原子转移/上限检查失败。 |

## 边界与证据

本包是确定性的进程内 reducer。它不持久化状态、不发送提交、不发现节点、不建立会话、不派生密钥、不加密内容，也不实现 E2EE。调用方负责持久化，并在依赖或授权者恢复后重试待处理输入。

群组包 smoke/model 轨迹覆盖逆序重放、重复投递、添加/移除/替换、上限拒绝、规范字节编码、授权者不可用及恢复、待处理哈希碰撞和显式阻塞的冲突分支。发布证据还必须在传输层测量 2、50、200 和 500 个主体，并覆盖授权者丢失、冲突修复、重连和队列上限。
