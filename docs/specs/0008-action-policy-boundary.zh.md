# 0008 动作审批策略边界

[English](0008-action-policy-boundary.md) | 中文

状态：已接受的 MVP 边界。

## 审批门槛

节点把审批回执视为策略决策，而不是通用状态更新。只有不可变信封满足 `policy.requiresApproval === true`，并且所选 `actionId` 出现在 `semantic.availableActions` 中时，才接受 `approved` 回执。动作仍必须处于 `requested` 或 `awaiting_approval`；缺少动作请求、已有终态决策或身份不匹配都会默认拒绝。拒绝可以记录一个已请求的动作，但不会授予审批权限。

Reducer 是纯函数且结果确定。调用者提供信封、事件摘要、动作 ID、之前的尝试、设备 ID 和评估时间。Reducer 返回接受的决策或有限错误；执行、通知和外部工具都不在这个边界内。

## 过期

`policy.expiresAt` 必须是 `null`/缺省，或是节点线格式接受的 ISO 时间戳。格式错误或非字符串值会在决策边界被拒绝。评估时刻等于或晚于 `expiresAt` 时审批已过期；拒绝仍是本地决策，不会执行动作。

## 决策身份

本地动作行把决策绑定到事件摘要（内容派生的事件 ID）、动作 ID、受众、授权者、策略版本和审批设备。信封提供这些字段时记录受众、授权者和策略版本；当前 profile 在缺少授权者时回退到 actor，缺少的协议字段存为 null。同一绑定的重复决策是幂等的。不同设备、策略身份、动作或终态都会被拒绝。

`POST /v1/receipts` 的线格式保持不变。签名作者身份、委托验证、群成员/key epoch、策略授权查询和执行尝试副作用要等各自的协议决策与存储契约确定后再实现。
